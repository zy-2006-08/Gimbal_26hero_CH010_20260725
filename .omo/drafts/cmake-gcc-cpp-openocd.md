## Decisions (with rationale)
- Force-compile the 3 mixed .c files as C++ via `set_source_files_properties(... PROPERTIES LANGUAGE CXX)` in the MAIN CMakeLists.txt — user chose "方案一" (keep filenames so CubeMX can regenerate). Do NOT rename files, do NOT edit their contents.
- User still uses CubeMX regen -> ALL edits go in main CMakeLists.txt, cmake/gcc-arm-none-eabi.cmake, and NEW files (openocd.cfg, keybindings.json). Do NOT edit cmake/stm32cubemx/CMakeLists.txt for user sources (it's regenerated). main.c/stm32f4xx_it.c are already in the CubeMX list; the LANGUAGE property is set from the main CMakeLists targeting those source files.
- Note: main.c & stm32f4xx_it.c are added to the target via the stm32cubemx INTERFACE lib. set_source_files_properties with a full/relative path in main CMakeLists must reference the same absolute source path for the LANGUAGE property to bind. Executor must verify the property actually takes effect (see QA).
- objcopy POST_BUILD in main CMakeLists (not toolchain file) so it attaches to the executable target.
- Flash via OpenOCD program elf; still generate hex/bin (near-zero cost, useful for drag-drop / release).
- Keybindings global, no `when` (user instruction).
